## MCU シート編集結果（2026-11-25、tools/sch_audit.py で検証済み）

- 削除: U4 TPS2116、J9 外部電源コネクタ、J1 QSPI 引き出しコネクタ、QSPI ラベル 12 個
- グローバルラベル化＋改名: SAI_BCLK→ENC1_A(PB3)、SAI_MCLK→ENC1_B(PB4)、SAI_DOUT→ENC2_A(PB5)、SAI_LRCLK→ENC2_B(PB6)、I2C_SDA→ENC3_A(PA8)、I2C_SCL→ENC3_B(PA9)、SAI_DIN→ENC4_A(PA10)、ADC1_IN2→ENC4_B(PA1=旧ポット)
- グローバルラベル化（改名）: UART_RX→PA15、UART_TX→PA2、ADC3_IN5→PB13、SPI_SCK→PF1、SPI_MISO→PB14、SPI_MOSI→PB15
- グローバルラベル化（同名）: ADC2_IN1(PA0)、ADC2_IN12(PB2)、ADC2_IN13(PA5)、ADC2_IN17(PA4) = スティック ADC
- 新設: スキャン 5 ピン（PC13=164_CLK、PC14=164_A、PC15=165_CLK、PB7=165_SL、PB9=165_QH）は現行メインボード回路図で no_connect だったため、no_connect を外しスタブ配線＋グローバルラベルを追加
- 残置（GUI 整理時に判断）: J2/J3/J5/J6 コネクタシンボルとその先のスタブ（ネットはグローバル化済みなので電気的には無害）、QSPI ピンのスタブ配線
- 監査で確定した実配線（.ioc の要約と一部相違）: スティックは RV2: X=PB2 / Y=PA0、RV3: X=PA4 / Y=PA5。ポットは PA1。USER_SW=PB10(SW2)、LED0=PB12
- 相違の理由（ユーザー説明 2026-11-25）: **STK が使っているメインボードは 1 つ前のリビジョン**で、リポジトリのメインボード回路図は最新リビジョン（TPS2116 等の外部電源まわりはこちらで追加された）。スキャンピンの未接続やネット名の対応のずれはこのリビジョン差による。STKEY は新規の一体基板なので、キーボード基板側の信号の行き先を正としてピン割り当てを自己完結させている

## 接続方式の調査結果（2026-11-25）

- KVL_STK 側のシート間接続は **グローバルラベル**（Q0〜Q7、PA15 等）と、ICs シート内のローカルラベル（164_A / 165_SL / POT0 / SCL / SDA / BCLK 等。モジュールフットプリントのピンに接続）
- メインボード側は全てローカルラベル（SAI_*、QSPI_*、I2C_*、ADC*_IN* 等）
- 統合方針: 両シートの受け渡しネットを **グローバルラベルに統一** して接続する

## ICs シート編集結果（2026-11-25、tools/sch_audit.py で検証済み）

- 削除: ADAU1761、MIC2005A、RV1 ポット、RV2/RV3 スティック、オーディオジャック ×2、I2C ヘッダ、C4NDY モジュール受け、およびネット解析で特定した周辺パッシブ 19 点（C69–C80 系デカップリング、R14/R15 I2C プルアップ、R16 MIC2005A イネーブル、R17–R20）
- 追加: PEC11R ×4（ENC1–4）。シンボル My_Parts:PEC11R を新規作成（ピン 1=A / 2=COM / 3=B / 4=SW1 / 5=SW2）。A/B は ENC*_A/B グローバルラベルへ 10k プルアップ（R25–R32）付き、COM と SW2 は GND、SW1 は ENC*_SW
- 追加: 74HC165 3 個目（U7）。押しスイッチ ENC1_SW–ENC4_SW を D0–D3 へ（10k プルアップ R21–R24）、D4–D7 は NC、DS は GND。スキャンチェーン順は **U7（エンコーダー押し）→ U3（Q0_2/Q1_2）→ U2（Q0–Q7）→ MCU** で、U7 の Q7 をローカルラベル 165_CHAIN で U3 の DS に接続。ファームウェアの読み取りは合計 24 ビットになる
- 追加: スティックコネクタ J10/J11（Conn_01x04、1=VCC / 2=X / 3=Y / 4=GND）。J10: X=ADC2_IN12 / Y=ADC2_IN1、J11: X=ADC2_IN17 / Y=ADC2_IN13
- 残置: J4（GPIO 拡張ヘッダ PA15/PA2/PB13/PB14/PB15/PF1）
- グローバルラベル整合: MCU↔ICs（22 ネット）、ルート↔ICs（Q0–Q7、Q0_2/Q1_2、QA–QD）、LED↔ICs（PA15）の全セット一致を監査で確認済み
- 編集時の教訓: シンボルのクローンは (mirror) を引き継ぐ（J4 の mirror y でピンが反対側に出た）。新規電源タップは既存の電源配線と座標が重なると短絡する（U7 VCC が U3 の GND シンボル座標と一致した）。配置後に必ず監査でピン→ネットを確認すること

## ユーザーによる再描画と検証結果（2026-11-25、コミット 83bfe3e）

- ユーザーが KiCad で全面再配置＋再アノテーション。新しい番号付け: 74HC165 = U1（Q0–Q7、末尾）/ U2（Q0_2・Q1_2）/ U3（ENC 押し、先頭）、74HC164 = U4、スティックコネクタ = J1/J2、MCU = U6、LDO = U5、USB-C = J3、SWD = J4
- Muse が実ファイルで再監査し、以下を確認済み:
  - マトリクスのプル抵抗（U1 の R5–R12、U2 の R13/R14）は**全て VCC へのプルアップ**で元設計どおり（スクリーンショットでは GND 側に見えたが実ファイルでは VCC）
  - X1 出力 → R26(33Ω) → U6 PF0 は無名ネットで直接接続され、**PF1 とは短絡していない**（PF1 は独立したラベルスタブ）
  - チェーン順 U3 → U2 → U1 → 165_QH、ENC1–4、J1/J2 のピン順、MCU のピン割り当て（ENC/ADC/スキャン）は設計どおり
- 観察事項: ICs シートにあった GPIO 拡張ヘッダ（旧 J4: PA2/PB13/PB14/PB15/PF1）は再描画で削除された。PA2/PB14/PB15/PF1 は MCU シートのグローバルラベルとしてのみ残る。意図的かどうかはユーザー確認待ち
- 2026-11-25 追加変更（ユーザー、コミット 1619cde「配線を整理」）: **ENC4 を PA10/PA1 から PB0/PB1 に付け替え**（全エンコーダーが近接ペアに統一。PA1/PA10 は予備に戻った）。あわせて PA15 のネット名を **RGB_LED** に改名（MCU・LEDs 両シートで一致、接続は維持）。設計書の割り当て表も追随済み
- PB13 の不整合は解消済み: 配線整理で MCU 側の PB13 ラベルが消え ICs 側（JP1 → LED D1）と切れていたが、2026-11-25 にユーザーが MCU 側ラベルを復活。両シートに PB13 が 1 つずつあることを監査で確認済み
- 2026-11-25 **RGB LED チェーン廃止**（ユーザー決定）: LEDs シート（Address_LED ×40 ＋ 100nF ×40）を削除し、ルートシートのシートボックスと .kicad_pro のシート一覧からも除去。MCU 側の RGB_LED グローバルラベルと PA15 のスタブ配線も削除し、PA15 は予備に戻した。小さいステータス LED（VBUS、LED0、PB13 の LED）は残置。背景: リバースマウント＋3.3V 駆動可のアドレス式 LED が存在しない（SK6812MINI-E は定格 3.7〜5.5V）
